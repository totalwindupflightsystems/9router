### Ring 2 input set
- `conc-q2-1` F `(watchdog-blocking,F,4.20)`: Can a network post stall heartbeat/scans? Answer: every connect/read has a finite timeout; heartbeat is emitted only after loop progress, so watchdog kills a wedged loop.
- `conc-q2-2` D `(scan-order,D,4.20)`: Must roots be ordered? Answer: no correctness order; round-robin avoids starvation. One root transaction commits independently.
- `conc-q2-3` O `(shutdown-coordination,O,4.20)`: SIGTERM during scan/send? Answer: stop scheduling, roll back active transaction, never start another send, checkpoint nothing ephemeral, close DB, exit before systemd timeout.
- `conc-q2-4` C `(transaction-duration,C,4.20)`: Full scan in one transaction? Answer: staging inserts may batch, but canonical promotion is one short set-difference transaction; one process avoids reader contention.
- `conc-q2-5` A `(inotify-acceleration,A,4.20)`: Add inotify queue? Answer: optional future wake-up only; never source of truth because overflow and downtime exist.

New signatures: lock-stale, wall-clock-jump, scan-overlap, send-overlap, backpressure.

### Ring 3 input set
- `conc-q3-1` F `(lock-stale,F,4.20)`: Does lock survive crash? Answer: kernel releases flock on process exit; no stale lease cleanup.
- `conc-q3-2` D `(clock-jump,D,4.20)`: NTP/DST? Answer: UTC wall clock defines persisted windows; monotonic time drives sleeps/backoff; unique window_end prevents duplicates.
- `conc-q3-3` O `(scan-overlap,O,4.20)`: New interval while scan active? Answer: set a due flag; do not run overlapping scans; next loop starts once current work ends.
- `conc-q3-4` F `(send-overlap,F,4.20)`: Multiple pending digests? Answer: deliver oldest first, one attempt at a time; no later digest overtakes an earlier pending digest.
- `conc-q3-5` C `(backpressure,C,4.20)`: Endpoint down for days? Answer: durable pending rows grow; local scans continue until disk reserve threshold, then fail loud rather than delete.

New signatures: fairness, late-event-order, idempotency-header, retry-jitter, starvation-proof.

### Ring 4 input set
- `conc-q4-1` O `(root-fairness,O,4.20)`: Slow root starvation? Answer: process roots round-robin and cap one completed scan per root per cycle; overdue status is a metric/alert.
- `conc-q4-2` D `(late-event-order,D,4.20)`: Event observed after its hour? Answer: ordered by commit observation time, not filesystem mtime; enters next unclosed digest.
- `conc-q4-3` X `(idempotency-header,X,4.18)`: Receiver support? Answer: send `Idempotency-Key: <digest-id>` when HTTP is chosen, but do not assume receiver honors it; body also includes id.

- `conc-q4-5` P `(starvation-proof,P,4.20)`: Verification? Answer: fake clock + slow root + failing endpoint test must show later roots scanned and watchdog progress or deliberate watchdog death.
