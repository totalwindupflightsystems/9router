## Battery and cascade

### Ring 1 input set

- `alert-q1-2` F `(wake-condition,F,4.17)`: What merits urgent signal? Answer: service crash-loop/watchdog failure, store unavailable/corrupt/full, root continuously unreadable, or pending digest age beyond configured threshold.
- `alert-q1-3` O `(first-action,O,4.17)`: What does signal contain? Answer: incident id, class, affected root/store, first command, journal location; never secret or full sensitive path by default.

## Required output — alert table

| Condition | Threshold | Severity | Responder | First action |
|---|---|---|---|---|
| schema/quick-check failure | immediate at boot | critical | operator | stop unit; preserve DB; run verify/restore runbook |
| disk full/I/O failure | immediate write failure or configured reserve breached | critical | operator | stop unit; preserve state; restore space without deleting pending rows |
| watchdog/process crash-loop | watchdog miss or systemd start-limit | critical | operator | inspect `systemctl status` and journal by incident id |
| required root unreadable | immediate; optional root after configured consecutive failures | high | operator | verify mount and service-user access; dry-run scan |
| pending digest backlog | oldest age > one digest period + measured grace | warning/high | operator | test endpoint/auth; do not purge outbox |
| digest recovered | first successful post after incident | info | operator | confirm incident closes |
| host/power loss | no local threshold possible | uncovered unless ESC-02 | operator/external monitor | external host/network check |

Every alert has a named first action; exact nonfatal thresholds remain measured configuration, not false precision.
