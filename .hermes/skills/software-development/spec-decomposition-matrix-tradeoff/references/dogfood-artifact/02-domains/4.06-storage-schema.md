## Battery and cascade

### Ring 1 input set
- `store-q1-1` D `(state-store,D,4.6)`: Files, JSONL, or relational store? Answer: one local SQLite database because scan promotion, event append, and digest assignment must commit together.
- `store-q1-2` F `(transaction,F,4.6)`: What must be atomic? Answer: canonical scan replacement + emitted events, and separately digest creation + assignment of event ids.
- `store-q1-3` O `(database-backup,O,4.6)`: How is it backed up? Answer: same CLI uses SQLite online backup API to a temp file, fsyncs, then atomic-renames into a dated snapshot.
- `store-q1-4` C `(database-growth,C,4.6)`: Capacity? Answer: unmeasured; current rows scale with file count and event rows with churn. U-001 requires a target-box benchmark and free-space threshold.
- `store-q1-5` A `(journal-mode,A,4.6)`: WAL or rollback journal? Answer: rollback journal with `synchronous=FULL` for one writer and simplest backup/recovery; WAL's concurrency benefit is not needed.

Answers forced D-004, D-005, D-006, and D-018.

### Ring 2 input set
- `store-q2-1` D `(schema,D,4.6)`: Which constraints carry correctness? Answer: unique root name/path, unique `(root_id,relative_path)`, unique digest `window_end_utc`, event→scan foreign keys, enum CHECKs, monotonic schema version.
- `store-q2-2` F `(partial-scan,F,4.6)`: What survives a crash? Answer: canonical tables remain pre-scan; orphan staging is removed on startup by scan status.
- `store-q2-3` O `(migration,O,4.6)`: How migrate? Answer: backup, `BEGIN IMMEDIATE`, version check, forward migration, invariant checks, commit; rollback is binary rollback plus restored pre-migration snapshot.
- `store-q2-4` C `(index-write-cost,C,4.6)`: Which indexes earn writes? Answer: only current-state lookup, pending digest, event window, and scan cleanup; each serves a named query below.
- `store-q2-5` A `(jsonl-store,A,4.6)`: Why not append JSONL? Answer: it makes current-state lookup and atomic event/digest assignment custom recovery machinery; lower initial code, higher correctness surface.

New signatures: integrity-check, disk-full, backup-consistency, schema-downgrade, fsync-proof.

### Ring 3 input set
- `store-q3-1` P `(integrity-check,P,4.6)`: What proves store health? Answer: startup `PRAGMA quick_check`, foreign keys ON, schema version exact, then a transaction smoke check before READY.
- `store-q3-2` F `(disk-full,F,4.42)`: What on SQLITE_FULL/I/O error? Answer: roll back, stop claiming readiness, journal a fatal error, and let systemd restart with rate limits; never prune pending data automatically.
- `store-q3-3` O `(backup-consistency,O,4.6)`: Why not copy the DB file? Answer: live copying can miss journal state; D-018 is modified to require SQLite backup API.
- `store-q3-4` X `(schema-downgrade,X,4.6)`: Old binary on new DB? Answer: fail closed with explicit version error; no automatic down-migration.
- `store-q3-5` P `(filesystem-rename,P,4.23)`: Is atomic rename available in the exercise environment? Answer: project probe `<scratch>/design-sandbox/probes/rename-b` exists after `mv`+`sync -d`, source absent; this proves the local exercise path only, not the future target filesystem.

New signatures: corruption-recovery, checkpoint-size, directory-fsync, restore-rehearsal, retention-vacuum.

### Ring 4 input set
- `store-q4-1` F `(corrupt-database,F,4.42)`: Recovery? Answer: stop writes; preserve corrupt file; restore newest verified snapshot; replay is impossible beyond the snapshot on one box, so disk-loss RPO is backup cadence, distinct from process-crash RPO=0 committed transactions.
- `store-q4-2` C `(database-vacuum,C,4.6)`: How reclaim retention space? Answer: batched DELETE; no automatic full VACUUM in the daemon; operator maintenance command with free-space precheck.
- `store-q4-3` O `(directory-fsync,O,4.6)`: Snapshot durability? Answer: fsync snapshot then parent directory after atomic rename; failure leaves prior snapshot intact.
- `store-q4-4` P `(restore-rehearsal,P,4.42)`: Proof? Answer: `filedigest verify-backup SNAPSHOT` opens read-only, quick-checks, and emits counts; release acceptance restores into a temporary state directory.
- `store-q4-5` A `(sqlite-swap,A,4.6)`: Swap path? Answer: export versioned JSONL via CLI before changing engines; high-volume evidence, not preference, would trigger it.

All outputs map to D-005/D-016/D-018/D-020 or U-001. Next signatures duplicate prior rows.

## Required output — DDL-equivalent sketch

```sql
roots(id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL, path BLOB UNIQUE NOT NULL, enabled INTEGER CHECK(enabled IN (0,1)), policy_json TEXT NOT NULL);
scan_runs(id TEXT PRIMARY KEY, root_id INTEGER NOT NULL REFERENCES roots, started_utc TEXT NOT NULL, finished_utc TEXT, status TEXT NOT NULL CHECK(status IN ('STAGING','COMMITTED','FAILED')), error_code TEXT);
scan_stage(scan_id TEXT NOT NULL REFERENCES scan_runs ON DELETE CASCADE, relative_path BLOB NOT NULL, size INTEGER NOT NULL, mtime_ns INTEGER NOT NULL, mode INTEGER NOT NULL, dev INTEGER, inode INTEGER, PRIMARY KEY(scan_id,relative_path));
file_state(root_id INTEGER NOT NULL REFERENCES roots, relative_path BLOB NOT NULL, size INTEGER NOT NULL, mtime_ns INTEGER NOT NULL, mode INTEGER NOT NULL, dev INTEGER, inode INTEGER, last_scan_id TEXT NOT NULL REFERENCES scan_runs, PRIMARY KEY(root_id,relative_path));
events(id TEXT PRIMARY KEY, root_id INTEGER NOT NULL REFERENCES roots, relative_path BLOB NOT NULL, kind TEXT NOT NULL CHECK(kind IN ('DISCOVERED','METADATA_CHANGED','DISAPPEARED')), old_json TEXT, new_json TEXT, observed_utc TEXT NOT NULL, scan_id TEXT NOT NULL REFERENCES scan_runs, digest_id TEXT REFERENCES digests);
digests(id TEXT PRIMARY KEY, window_start_utc TEXT NOT NULL, window_end_utc TEXT UNIQUE NOT NULL, body TEXT NOT NULL, body_sha256 TEXT NOT NULL, status TEXT NOT NULL CHECK(status IN ('PENDING','DELIVERED','ABANDONED')), created_utc TEXT NOT NULL, delivered_utc TEXT, receipt TEXT);
delivery_attempts(id INTEGER PRIMARY KEY, digest_id TEXT NOT NULL REFERENCES digests, attempted_utc TEXT NOT NULL, result_class TEXT NOT NULL, http_status INTEGER, detail_redacted TEXT);
meta(schema_version INTEGER NOT NULL, last_completed_window_utc TEXT);
```

Index table:

| Index | Query served | Write cost |
|---|---|---|
| PK file_state(root_id,relative_path) | compare staged path/current state | one B-tree update per changed file |
| scan_stage(scan_id,relative_path) PK | stage insert and set difference | one temporary B-tree insert per observed file |
| events(digest_id,observed_utc) | select unassigned committed events by cutoff | one index write per event |
| digests(status,window_end_utc) | oldest pending retry | one index write per digest/status transition |
| scan_runs(status,started_utc) | orphan-stage cleanup | one index write per scan |

Migration/rollback: stop service; verified online backup; run versioned forward migration in one immediate transaction; quick-check and invariant queries; restart; if validation fails, restore snapshot and prior binary. Mixed-version operation is forbidden because one supervised instance owns the DB.
