### Ring 2 input set

- `fail-q2-2` F `(root-unavailable,F,4.42)`: Missing mount/permission? Answer: mark root scan FAILED, preserve prior file state, alert after threshold; do not emit mass deletions.

### Ring 3 input set
- `fail-q3-1` F `(notifier-failure,F,4.42)`: Same destination is down? Answer: notifier writes independent journald failure; no same-box design can guarantee remote delivery through a dead network.
- `fail-q3-2` O `(crash-loop,O,4.12)`: Control? Answer: systemd restart with delay and start-limit; OnFailure helper fires after failure state, with its own timeout.
- `fail-q3-3` F `(host-down,F,4.42)`: Can it tell the operator? Answer: no; ESC-02 compares adding an external dead-man monitor versus accepting this blind spot.
- `fail-q3-4` F `(transient-file-gap,F,4.42)`: File appears/disappears while down? Answer: unrecoverable from a later scan; ESC-01 sets the product guarantee.
- `fail-q3-5` O `(backup-loss,O,4.42)`: Backup on same disk? Answer: protects operator/schema mistakes, not media loss. Off-box copy is optional and would be another external dependency.

New signatures: alert-dedup, recovery-time, backup-rehearsal, watchdog-lie, shutdown-timeout.

### Ring 4 input set
- `fail-q4-1` F `(alert-dedup,F,4.17)`: Restart storm spam? Answer: deterministic failure incident id per boot/start-limit window; receiver may dedupe; journald preserves every attempt.
- `fail-q4-2` C `(recovery-time,C,4.42)`: RTO? Answer: no measured target; process restart target is next systemd attempt, database restore depends on size and U-001 benchmark. Do not invent minutes.

## Required output — failure table

| Failure | Detection | Blast radius | Recovery | RTO |
|---|---|---|---|---|
| process crash mid-scan | systemd exit + non-COMMITTED scan | current scan only | rollback/orphan cleanup/reconcile | next restart attempt; measure on target |
| crash after remote accept | PENDING digest despite possible receiver copy | duplicate digest | resend same id; receiver dedupe if supported | next retry |
| unreadable/missing root | failed root scan | one root; prior state preserved | restore mount/permission then reconcile | operator-dependent |
| endpoint down | timeout/non-2xx | notifications delayed, scans continue | backoff and oldest-first replay | endpoint-dependent |
| disk full/I/O failure | SQLite error + free-space check | all durable writes | free/replace storage; preserve pending data | operator-dependent |
| DB corruption | quick_check/open failure | history/state DB | preserve evidence, restore verified backup, reconcile | size-dependent; benchmark U-001 |
| process hung | watchdog missed after no loop progress | all scheduling | systemd kill/restart; one-shot alert | watchdog + restart interval |
| whole host down | no local signal possible | all functions | external action | invisible unless ESC-02 chooses external heartbeat |
| disk/media loss | DB unavailable | history since backup | replace disk, restore backup, reconcile current files | backup/size-dependent |

Top runbooks: (1) crash-loop/disk-full: inspect independent journal, stop unit, preserve DB, restore space, quick-check, restart; (2) root unreadable: verify mount and service-user permission, run `scan --dry-run ROOT`, resume; (3) corruption: stop, copy corrupt DB, verify newest backup, restore to new file, reconcile, record historical RPO gap.
