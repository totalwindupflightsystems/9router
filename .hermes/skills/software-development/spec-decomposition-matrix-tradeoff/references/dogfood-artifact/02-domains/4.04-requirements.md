## Required output — requirements

- R1: Given valid roots, a completed scan records each observed regular file by root-relative path and stat metadata.
- R2: Startup and periodic reconciliation discover files still present even when their creation occurred while the process was down.
- R3: A crash before scan promotion leaves canonical state unchanged; a crash after commit leaves both state and events committed.
- R4: Every nonempty UTC hour eventually has one durable digest row whose included event ids cannot be assigned to another digest.
- R5: Remote delivery is retried oldest-first with a stable digest id; duplicate receipt is permitted, silent local abandonment is not.
- R6: The service starts at boot, restarts after failure, and watchdog liveness proves scheduler progress.
- R7: Process/service failure triggers an independent one-shot notification attempt and a journald record.
- R8: Invalid config/schema/store integrity prevents READY and produces a specific operator action.
- R9: The service never follows symlinks or reads file content by default.
- R10: Backup and restore preserve all committed tables and are verifiable before replacement.

Non-goals: distributed HA (conflicts with one-box preference); file-content backup (different job); exactly-once remote posting (unprovable across ack loss); guaranteed transient capture during downtime (requires ESC-01 architecture); whole-host self-alert (physically impossible, ESC-02); GUI/accounts/tenancy (no user class); sub-second real-time notification (hourly job); rename reconstruction/content hash (unneeded content semantics).

Acceptance bar: all BEFORE-BUILD ids in `03-decisions.md` appear in its invariant→test map; crash injection at each named boundary passes; a clean reboot produces no lost committed event and retries pending digest with identical id/body.
